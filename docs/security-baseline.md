# 安全边界

## 身份与权限

- 管理 API 使用会话认证；本地登录校验账号与密码，GitHub 登录受允许名单约束。
- 修改本地账号或密码必须提交当前密码，与登录共用同一并发门限；会话本身不是凭据证明。
- 允许名单的条目可以是用户名，也可以是 GitHub 账号数字 ID（`12345` 或 `id:12345`），两种形式可混用。
  用户名可被本人放弃后由他人注册，只写用户名的名单会放行当时持有该名称的账号；需要固定身份时改用 ID。
  每次接受登录都会把用户名和 ID 一并记入日志，便于替换。
- 节点永久令牌只在创建/轮换时展示，数据库保存摘要；轮换或删除会退休旧连接。创建节点和轮换令牌都要求 HTTPS 域名入口，因为两者都在响应里返回长期凭据。
- 注册窗口使用短期 key 换取独立节点令牌。节点列表中的 `node-{id}` 仅用于定位，不能认证。
- 公开页默认关闭；匿名投影不包含 IP、主机名、备注或凭据。权限在 Hub 判断，不依赖按钮隐藏。
- 密码校验、连接、历史查询与上报都有准入/尺寸限制；匿名与管理各有独立的历史查询与实时连接配额。两个 WebSocket 同时限制消息与帧尺寸为 64 KiB。具体常量与测试见源码。
- 两套前端页面返回 `Content-Security-Policy`、`X-Frame-Options: DENY`、`X-Content-Type-Options` 和 `Referrer-Policy`。策略按实际返回的 HTML 计算内联脚本哈希，不使用 `script-src 'unsafe-inline'`；`frame-ancestors 'none'` 防止管理界面被嵌套。

## 传输与分发

Hub 默认回环监听，可信反向代理终止 HTTPS；管理员创建/安装节点要求 HTTPS 域名。

两类转发头的信任级别不同，是有意区分：`X-Forwarded-For` 只在对端为回环时采信，因为它用于限流计数和地址展示，可被调用方自由伪造；
`X-Forwarded-Proto` 与 `Host` 用于判断入口是否为 HTTPS 域名，前提是代理不可绕过——Hub 端口一旦对外可达，调用方即可自设这两个头。
因此监听非回环地址时 Hub 会在启动日志中警告，部署要求见 [部署](deployment.md) 的反向代理一节。
Agent 默认验证 TLS。显式 insecure 模式属于受控环境选项，不改变默认安全行为。
安装器只下载本 Hub 的已验证精确版本工件并校验摘要；永久令牌由终端读取，不写入 shell 历史或 argv。
只提供内置界面及本地国家数据库，不在运行时下载并执行第三方主题或可变 latest 二进制。

## 数据与运维

DuckDB 文件、WAL、spill、锁与 bootstrap 凭据限制为服务账号可读写。数据库和备份仍包含敏感管理配置。
恢复先验证归档、schema、关系与摘要，在文件替换栅栏内切换；失败保留或恢复旧库，不恢复旧登录会话。
日志、截图、CI 报告不得携带永久凭据或生产数据库。测试使用独立回环实例和合成数据。
发布只复用已验收字节，按 [发布流程](release.md) 核对来源和完整性。

本文件描述实现边界，不代表全面安全审计、完整 SBOM、密码学擦除或所有部署环境的保证。
