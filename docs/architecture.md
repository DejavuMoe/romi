# 运行架构与并发边界

Hub 是一个 Rust 进程，内嵌管理后台、公开页和 DuckDB；每台 Linux 主机运行一个 Agent。模块责任与端到端数据流见[代码导览](codebase-guide.md)。

| 路径 | 处理方式 | 上限 |
| --- | --- | --- |
| HTTP 请求 | 请求体在路由前受限；恢复备份的上传由面板按 4 MiB 分片提交 | 请求体 64 KiB；恢复分片单请求 ≤ 8 MiB |
| Agent 上报 | 单节点会话锁保持报告顺序；数据库变更经单 writer 提交后返回 | WebSocket 消息与单帧 64 KiB；Hub 向单个 Agent 的推送队列 16；writer 队列 512，单批最多 256 个遥测操作 |
| 实时展示 | 快照由 Agent 已发布的内存副本加上 DuckDB 中的节点配置与累计流量组成，公开/管理受众分别缓存，每个受众约 1.9 秒重建一次 | 每 2 秒推送；匿名连接 64（每个来源地址最多 4，IPv6 按 /64 计），管理连接 32 |
| 历史与备份 | 历史请求先准入，超出立即返回 503 而不排队，再由分析 reader 查询；备份读取同一 MVCC 快照 | 历史并发匿名 4、管理另有 2，分析 reader 3，历史查询 30 秒中断上限；窗口匿名 7 天、管理 1 年 |
| 登录 | argon2 密码校验，超出并发即拒绝而不排队 | 同一时刻 1 个校验；每地址失败 5 次锁定 15 分钟 |
| TCP 探测 | Hub 向在线 Agent 推送任务，Agent 保留未变化任务的计时器 | 每节点最多 64 个任务，DNS 阻塞线程最多 4 个 |
| 通知 | 扫描连接和数据库状态，事件进入进程内队列后逐渠道发送 | 队列 64，状态扫描每 30 秒 |

恢复或压缩数据库文件时的替换栅栏、写入排队与 generation 规则见[存储](storage.md)；身份与公开数据边界见[安全边界](security-baseline.md)。
