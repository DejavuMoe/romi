# 运行架构与并发边界

Hub 是一个 Rust 进程，内嵌管理后台、公开页和 DuckDB；每台 Linux 主机运行一个 Agent。模块责任与端到端数据流见[代码导览](codebase-guide.md)。

| 路径 | 处理方式 | 上限 |
| --- | --- | --- |
| Agent 上报 | 单节点会话锁保持报告顺序；数据库变更经单 writer 提交后返回 | writer 队列 512，单批最多 256 个遥测操作 |
| 实时展示 | 读取 Agent 已发布的内存副本，分别缓存公开/管理受众快照 | 默认每 2 秒推送；匿名连接 64，管理连接 32 |
| 历史与备份 | 历史请求先准入，再由分析 reader 查询；备份读取同一 MVCC 快照 | 历史并发 4，分析 reader 3，历史查询 30 秒中断上限 |
| TCP 探测 | Hub 向在线 Agent 推送任务，Agent 保留未变化任务的计时器 | 每节点最多 64 个任务，DNS 阻塞线程最多 4 个 |
| 通知 | 扫描连接和数据库状态，事件进入进程内队列后逐渠道发送 | 队列 64，状态扫描每 30 秒 |

恢复或重写数据库文件时，替换栅栏等待现有 reader 和在途报告，并拒绝旧 generation 的排队写入。普通保留期清理与备份快照不替换文件。DuckDB 的内存参数只限制引擎预算，不是 Hub 整体 RSS 上限。具体事务、文件和备份行为见[存储](storage.md)；身份与公开数据边界见[安全](security-baseline.md)。
