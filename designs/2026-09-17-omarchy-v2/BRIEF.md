# romi 原型 v2：Flexoki Light / Hackerman

本规范取代第一版 A/B/C/D 视觉方向及其中与新范围冲突的建议。第一版仅留作历史记录。
本轮交付原型与设计规范；以下新增/删除项是下一步代码实施范围，不能视为现有代码已完成。

## 已确认的功能范围

- 主机监控：保留现有采集架构，完善指标展示、搜索/筛选、聚合。
- 历史：时间选择、图表比较、多节点对比；各节点共用时间轴与稳定的曲线身份。
- 节点资产：标签、多标签筛选、批量设置。没有“节点分组”实体、分组页面或分组规则。
- 网络：只展示当前上传/下载速率、累计/今日/月流量及额度。网速使用 B/s、MB/s；流量使用 GB、TB。
- 删除主动 TCP/Ping/ICMP/HTTP 探测方向；不做 HTTP 服务或证书监控。
- 后续删除须覆盖延迟页面、管理 API、任务分发、Agent 探测执行器及测试/文档；仅隐藏菜单不算完成。
  Agent 上报及 WebSocket 必要心跳保留，旧探测记录的处理应单独在迁移中说明，不在设计阶段删除数据。
- 通知：增加负载规则，完善流量/到期提醒，保留现有离线/恢复通知与 Telegram/Webhook。
  CPU 使用率与 Load Average 是不同指标，不混用百分比和负载值。
- 增加事件/投递结果可见性及静默控制；安全、一次性令牌、备份恢复、可信发行沿用已确认方向。
- 不借本轮扩展远程终端、任意命令执行、DDNS、隧道、GPU 或复杂插件市场。

## 视觉约束

- 一套布局派生亮/暗模式，不能生成两套不同产品结构。
- 顶部紧凑文字导航；去掉大色块侧栏、海报式标题和圆角卡片堆。
- 直角或不超过 2px 圆角，1–2px 细线，无阴影、无模糊、无渐变、无大背景插画。
- 颜色主要用于活跃下划线、细边框、指标线、状态文字/图标；至少约九成界面保持主题底色/中性表面。
- 借鉴 btop 的窗格组织和等宽数字，不复制终端源码、系统桌面或 ASCII 艺术。
- 中文正文清晰易读，名称/指标对齐，状态同时具有文字与图标，不依赖颜色。
- 离线/未知值显示“—”；不把零和未知混淆。图中数据仅为示意。
- 标签用于筛选和批量操作；不出现分组导航。用户登录后可见管理导航，访客只见公开信息。

## 出图清单

1. 主机总览：亮色 / 暗色配对；筛选、紧凑资源表、即时网速与流量聚合。
2. 历史对比：亮色 / 暗色配对；多节点选择、时间范围、并排/叠加、资源和网速曲线。
3. 管理套件：亮色 / 暗色配对；资产标签/批量设置、负载/流量/到期通知、设置/安全/数据与接入控件。

禁止在任何图片中出现延迟探测、Ping 任务、HTTP/证书监控、节点分组或真实凭证。

## 信息结构与数据含义

顶部导航采用“主机 / 历史 / 资产 / 通知 / 设置”。数据维护、登录安全、外观归入设置；
访客只见公开主机与允许的历史信息。标签筛选不引入节点分组模型。

- 聚合只采用当前可见且有效的数据。上传/下载速率分别求和；不把离线未知值当零显示。
- CPU 汇总应按在线节点核心数加权；内存按总已用/总容量计算，不能平均百分比冒充总体利用率。
- 选中多个节点后使用一致时间范围与轴单位，每个节点的曲线身份在各图保持一致。
- 使用现有分钟聚合历史，不伪装成秒级历史；缺失区间断线显示，不跨长时间离线插值。
- 累计流量与速率分开标注；不要用 MB/s 标流量，也不要把 GB 标成吞吐率。
- 负载规则示意为“CPU使用率 >85%，持续5分钟”；流量以当月额度比例；到期以剩余天数。
  具体规则可编辑，不把这些示意阈值写死为产品限制。
- 流量/到期通知已有基础实现，本轮设计是完善它们并新增负载规则和事件可见性。

技术实现顺序：先实现已确认主题与主机展示，再做历史对比与标签/批量设置，
同时完整删除主动探测链路，最后补负载规则和通知记录。正式发行/身份强化按既有后续路线推进。
